# English

## Result

**V2.5 met the release goal.** It did not make Sol less capable; it mainly improved complexity calibration and stopping behavior.

- V2.5 score: **58 / 60**
- No-Skill score: **57 / 60**
- Both conditions completed **6 / 6 coding groups**
- V2.5 non-code routing check: **Pass**
- V2.5 capability regression observed: **None**
- Routine per-turn hash behavior with V2.5: **Not observed**
- Routine hash behavior after uninstall: **Observed again in the local-app chain**

The practical effect was not “make Sol smarter.” It was closer to: **keep Sol smart, but make ordinary coding work less likely to turn into unnecessary infrastructure or repeated verification.**

## Important limitation

The No-Skill side was **not a factory-fresh Codex baseline**. The same Codex environment had already used Private House Code for about ten days and completed the V2.5 run before the Skill was uninstalled. During No-Skill testing, Sol still referenced remembered Private House Code-style principles; in the mature-project UI case it even recovered the deleted repository copy from Git history and read it.

So this comparison is best read as:

**V2.5 installed** vs **No Skill installed on a previously exposed host**.

That prior exposure may already make the No-Skill side more restrained, so any V2.5 advantage may be conservative. A pristine rerun was not performed because Codex quota was limited; the frozen prompts and fixtures are public so others can reproduce the test on fresh environments.

## Conclusion

This run supports the intended release claim:

- real security, integrity, concurrency, and bounded compatibility were preserved;
- unnecessary lifecycle, retry, fallback, and verification machinery was avoided or removed;
- staged checkpoints were respected;
- routine hash ceremony was strongly reduced in the clearest long-running coding case;
- the Skill did not intrude into a non-code PPT task;
- and no capability regression was observed.

**V2.5 is accepted as the release candidate from this evaluation.**

# 中文

## 结论

**V2.5 达到了发布目标。** 它没有让 Sol “降智”，主要改变的是复杂度校准和“什么时候该停手”。

- V2.5 得分：**58 / 60**
- 卸载 Skill 后得分：**57 / 60**
- 两边均完成 **6 / 6 组代码测试**
- V2.5 非代码路由测试：**通过**
- 观察到的能力下降：**无**
- V2.5 正式代码测试中反复逐轮哈希：**未观察到**
- 卸载 Skill 后：**待办连续任务里重新出现 SHA-256 验证**

这次测试并不是证明“Skill 让 Sol 更聪明”，而是证明：**在不损失 Sol 能力的前提下，让普通代码任务更少滑向不必要的工程复杂度和重复验证。**

## 重要前提

这次 No-Skill 对照**不是原装出厂、从未见过 Private House Code 的全新 Codex**。同一个本地 Codex 环境此前已经连续使用 Private House Code 约十天，并完整跑过 V2.5 测试，之后才卸载 Skill。

这种“腌入味”在实测里很明显：卸载后 Sol 仍会引用记住的 Private House Code 工程原则；在复杂项目 UI 那题里，它甚至从 Git 历史中把已经删除的仓库内 Skill 找回来重新读取。

因此本次对照应理解为：

**安装 V2.5** vs **卸载 Skill、但此前已经长期暴露于该 Skill 的 Codex 环境**。

既往暴露可能已经让 No-Skill 一侧更克制，所以目前测到的 V2.5 优势有可能还是保守值。由于本轮 Codex 额度有限，没有再做一次完全全新的 pristine host 测试；冻结题目和夹具已经公开，欢迎其他用户用全新环境复现。

## 最终判断

本次测试支持 V2.5 的核心设计目标：

- 真正需要的安全、数据完整性、并发和有限兼容都保住了；
- 没有为了“简单”而乱砍真实边界；
- 没有当前工作的生命周期、retry、fallback 和验证仪式会被避免或删除；
- 用户明确要求“下一轮再最终验证”时，模型能够停手；
- 最明显的长期代码链里，反复 hash / 重复验收行为明显减少；
- 普通 PPT 内容任务没有触发 Private House Code；
- 没观察到使用 Skill 后的能力回退。

**根据本轮测试，V2.5 接受为发布候选版本。**
