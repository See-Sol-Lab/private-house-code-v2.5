## 一句话结论

**V2.5 达到了目标：没有让 Sol 降智，而且节约将近一半的费用，终于不会哈希fallback满天飞了。**

- V2.5：**58 / 60**
- 卸载 Skill 后：**57 / 60**
- 两边都完成了 **6 / 6 组代码测试**
- 非代码任务不会乱触发 Private House Code：**通过**
- 使用 V2.5 后观察到能力下降：**没有**
- V2.5 正式代码测试中反复逐轮哈希：**没看到**
- 卸载后：**待办连续任务里 SHA-256 又回来了**

所以这次测试不是证明“Skill 让 Sol 更聪明”，而是证明：**Sol 还是那个 Sol，但更容易把力气花在真正需要的地方，而不是重复验证、乱加 fallback、把小功能盖成银行。**

## 先说一个很重要的前提

这次 No Skill 对照**不是原装出厂、从来没见过 Private House Code 的全新 Codex**。

这个本地 Codex 此前已经连续用了大约十天 Private House Code，又完整跑过 V2.5 测试，之后我们才把 Skill 卸载。

所以它已经有点“腌入味”了：

- 卸载后，Sol 仍会提到自己记住的 Private House Code 风格原则；
- 在复杂项目 UI 那题里，它甚至从 Git 历史里把已经删除的 Skill 找回来又读了一遍。

因此这次实际比较更准确地说是：

**安装 V2.5** vs **卸载 Skill、但已经长期接触过这套工程习惯的 Codex**。

这反而可能让 No Skill 一侧表现得比真正原装裸机更克制，所以目前测到的 V2.5 优势有可能还是保守值。

由于作者 Codex 额度有限（真的快烧没了，大家体谅一下 ），这次没有再买一套“从未见过 Private House Code”的全新环境重跑。测试题和夹具已经公开，欢迎其他用户拿自己的新环境复现。

## 我们真正想验证的几个点

### 1. 简单，不等于乱砍安全

公网密码重置这题里，V2.5 保住了随机 token、摘要存储、过期、一次性使用、限流、统一账号响应、会话失效等真实安全边界。

### 2. 简单，也不等于把并发和兼容删掉

SQLite 那题里，真实事务、锁等待和一周旧客户端兼容都保住了。

### 3. 真正没用的复杂度，确实敢删

十状态导入工具里，没有当前工作的生命周期状态、恢复器和 `--recover` 都被删掉，同时保住了整批事务回滚和人工重试。

### 4. Retry / fallback / hash 真的被约束住了

Weather 题没有长出 retry framework、circuit breaker、第二天气源、队列或后台修复服务。

连续待办任务里，V2.5 明显更能在阶段性任务完成后停手；卸载后又重新出现了更重的验证和 SHA-256。

### 5. 不影响普通非代码任务

用一个全新的 Work 对话让 Sol 设计 5 页 PPT 内容时，宿主调用的是官方 Presentations Skill，没有调用 Private House Code，也没有把代码工程流程带进普通写作任务。

## 最终判断

**V2.5 通过本轮测试，接受为发布候选版本。**

它做到了最重要的一件事：

> **不是把 Sol 变笨来省事，而是让 Sol 继续聪明，同时少做那些当前根本没工作的复杂工程和重复验证。**
